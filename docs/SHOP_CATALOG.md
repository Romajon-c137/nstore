# Каталог nStore — `/shop`

**Цель:** «Открыл → нашёл → добавил → заказал». За 5–10 секунд клиент понимает,
что продаёт nStore, где нужный товар, сколько он стоит и как его заказать.

---

## 1. Анализ текущего nStore.kz

| Что есть сейчас | Проблема для заказа |
|---|---|
| Лендинг (`/`) — промо-бар, hero-баннер, 12 блоков (условия, шаги, отзывы, форма) | Каталог — один блок из многих; до товаров надо пролистать рекламу |
| Кабинет · Каталог — сайдбар из ~70 разделов 1С, карточка 108 px с артикулом, «#sku · vol», «Упаковка», «оптовая цена / ед.» | Структура учёта вместо понятных категорий, много мелкого текста, маленькие фото |
| SEO-страницы `/catalog/:slug`, `/product/:slug` | Не для заказа: нет корзины, только WhatsApp |
| Повтор заказа — только из истории в кабинете, заменяет корзину целиком | Нет «частых товаров», «избранного», добавления без потери текущего подбора |

## 2. Визуальный стиль каталога

Каталог `/shop` оформлен по макету (октябрь 2026) — отдельно от зелёного стиля лендинга и кабинета:

- **Кнопки и ссылки:** синий `#1E50C8` (hover `#1843A8`, мягкий фон `#EAF0FC`).
- **Акцент:** тёмно-синий `#12306E` — логотип `nStore`, активная категория, плавающая корзина, бейдж счётчика.
- **Поверхности:** белый фон страницы, карточки `#F5F7FA` без теней; фото на карточке через `mix-blend-mode: multiply`, поэтому белый фон фотографий не виден.
- **Текст:** Onest, `#0F1B33` / `#5B6578` / `#8D96A6`.
- Все цвета — CSS-переменные `--sh-*` в начале `src/pages/shop/shop.css`; смена палитры = правка одного блока.

## 3. Категории

~70 разделов 1С (см. `migration/redirect-map.md`) сведены к 9 витринным —
правилами в `src/pages/shop/categories.ts`, без изменений в 1С:

**Кофе · Молоко · Сиропы · Соусы · Напитки · Чай · Расходники · Оборудование · Другое**

Правила упорядочены («стакан для кофе» → Расходники, «сироп для чая» → Сиропы,
«молочный шоколад» → Другое). Пустые категории не показываются.

## 4. Структура

```
/shop                      Каталог — «Что я могу купить?»
  ├─ Часто заказываете     (только клиент с историей; «Добавить всё»)
  ├─ Популярное            (4 товара, по одному из категории)
  └─ Все товары            + кнопка «Фильтры»
/shop?c=milk               Категория — «Какие товары здесь есть?»
/shop?q=…                  Поиск (мгновенный, на клиенте)
/shop?p=<id>               Товар — «Что это и сколько стоит?» (шторка поверх каталога)
/shop?view=mine            Мои закупки: Повторить заказ · Часто · Недавно · Избранное
Корзина (шторка)           «Что я заказал и сколько это стоит?»
/cabinet?tab=orders        Заказ — «Когда и куда доставят?» (существующий экран)
```

Состояние в URL: ссылкой можно поделиться, «Назад» закрывает товар.

| | Desktop ≥1024 | Tablet 600–1023 | Mobile <600 |
|---|---|---|---|
| Категории | плитки с иконками под шапкой | сетка плиток 4×2 на главной | то же |
| Главная | плитки → баннер → Популярное (5) → Часто заказывают (5) → Все товары с чипсами | то же, 3 в ряд | то же, 2 в ряд |
| Категория | плитки + подразделы чипсами («Зерновой», «Молотый»…) | «←  Кофе» + чипсы | то же |
| Поиск | сетка | список строк с кнопкой «+» | то же |
| Корзина | иконка со счётчиком и суммой + плавающая плашка справа внизу | плашка над нижним меню | то же |
| Навигация | шапка: Повторить заказ · Войти · Корзина | нижнее меню: Главная · Каталог · Корзина · Заказы · Профиль | то же |
| Товар / фильтры / корзина | модалка / панель справа | полноэкранные страницы со стрелкой «назад» | то же |

Кнопки и степперы — 44 px (52 px на странице товара).

## 5. Карточка

Фото (белый фон, одна высота) → название (2 строки) → фасовка «1 л • 2,5%» →
цена «630 ₸ за шт. · по 12 шт» → «+ В корзину» → после добавления «− 24 +» (2 кор.).

Варианты (жирность/объём) склеиваются в одну карточку с переключателем —
`groupProducts()` в `normalize.ts`. Склейка не происходит, если подписи вариантов
совпадают (значит, это разные товары).

## 6. Данные и интеграции

```
UI (ShopPage и компоненты)
   │  только типы из types.ts
   ▼
hooks.ts ── useShopData / useCart / useFavorites
   │
   ▼
source.ts ── CatalogSource { products, customer, pricing, orders, locations, placeOrder }
   ├─ supabaseSource   (таблица products ← sync_1c_products.py из 1С)
   ├─ demoSource       (VITE_CATALOG_SOURCE=demo — дизайн-ревью без БД)
   └─ …1С HTTP / REST  (новый адаптер; UI не меняется)
```

`CatalogProduct` содержит все поля из ТЗ: `id, sku, name, brand, category, subcategory,
description, image, images, unit, package, price, oldPrice, stock, availability,
barcode, weight, volume, attributes, isPopular` (+ `step`, `minQty`, `priceTiers`,
`priceLists`, `expectedDate`, `warehouses`, `documents`). `isFavorite` и
`isFrequentlyOrdered` — не свойства товара, а данные клиента: избранное (`useFavorites`)
и статистика заказов (`b2b.ts`).

### Коммерческая логика (`pricing.ts → resolvePrice`)

Приоритет: персональная цена → прайс-лист договора (опт `price_tp` / топ `price_top`)
→ скидка договора → скидка на раздел → оптовая ступень по количеству → базовая цена.
Кратность (`step` = `box_qty`) и минимальный заказ (`minQty`) соблюдаются степпером.
Минимальная сумма заказа (30 000 ₸) — в `src/data/placeOrder.ts`, общая с кабинетом.

Клиенту показывается только нужное для решения: цена, единица, кратность,
«Под заказ · 14 окт» / «Осталось 3». Остальное — в «Характеристиках».

### Оформление

- **Клиент:** RPC `place_order` (тот же путь, что в кабинете — `src/data/placeOrder.ts`),
  выбор точки доставки, проверка остатков, номер заказа.
- **Гость:** «Заказать через WhatsApp» + «Войти — оптовые цены и заказ онлайн».
  Корзина гостя переносится в аккаунт после входа.

## 7. Что дальше (не блокирует запуск)

- Колонки `is_popular`, `min_qty`, `old_price`, `brand`, `barcode` в `products` — `normalize.ts`
  их уже понимает; после миграции достаточно добавить их в `select` в `source.ts`.
- Избранное — сейчас в `localStorage` устройства; для синхронизации между
  устройствами нужна таблица `favorites (user_id, product_id)`.
- Оптовые ступени `priceTiers` и остатки по складам — заполнить в адаптере, когда
  появятся в 1С/API; UI их уже показывает.
- Корзина хранится в `localStorage`; серверная корзина (`useServerCart`, таблица `cart`)
  может заменить её без правок UI.
