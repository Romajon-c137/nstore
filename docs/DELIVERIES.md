# Доставки (водители)

Водитель получает бумажную накладную на складе «Алаш», в CRM выбирает доставки по адресу
и отмечает результат. Статус и фото подписанной накладной уходят в 1С.

```
1С OData (Расходная накладная, склад Алаш, проведённые, −14…+7 дней)
   └─ edge sync-onec-deliveries (cron 3,18,33,48 * * * *) ─► delivery.invoices
CRM /crm/deliveries (роль logist = водитель)
   └─ rpc dl_action ─► delivery.status + delivery.events, фото ─► Storage delivery-docs/<ref>/<ts>.jpg
edge delivery-to-onec (cron */5) ─► POST 1С /hs/nstore_delivery/status
   └─ доп. реквизит «Статус доставки» + присоединённый файл (расширение onec_extension_delivery.bsl)
```

## Водители и 1С
Каждый водитель CRM (роль logist) привязывается админом к физлицу и автомобилю 1С: «Доставки → Водители».
Без привязки взять накладную нельзя. При «Беру» привязка фиксируется в `delivery.status`
(`onec_driver_ref`, `onec_vehicle_ref`), расширение 1С заполняет «Водитель» и «Автомобиль» накладной
(«Подписи и другие реквизиты» → «Перевозка»); при «Отказаться»/сбросе — очищает.
Итоги месяца по водителям — «Доставки → Итоги месяца» (`dl_report`), в 1С — отбор по полю «Водитель».

В выгрузке только операция «Продажа покупателю»: возвраты поставщику (тоже расходные накладные) не попадают,
возвраты от покупателя — это приходные накладные, их нет в выгрузке вовсе.

## Статусы
| Код | В CRM | В 1С («Статус доставки») | Кто |
|---|---|---|---|
| waiting | Ожидает | (пусто) | по умолчанию / «Отказаться» / сброс админом |
| taken | В пути | В пути | водитель «Беру в доставку» |
| delivered | Доставлено | Доставлено | водитель, **обязательно фото подписанной накладной** |
| returned | Возврат | Возврат | водитель, обязательна причина |

Одну накладную может взять только один водитель. Закрытую накладную может сбросить только admin.
В списке нет розницы («Розничная реализация…»), Kaspi и внутренних передач ТОО ↔ ИП.

## Доступ
`role_permissions.module = 'deliveries'`: admin и logist — full, manager — view (видит всё, без действий), client — none.
RPC: `dl_list`, `dl_action`, `dl_history` (admin/manager/logist); служебные `dl_sync_invoices`, `dl_log_run`,
`dl_push_queue`, `dl_push_done` — только service_role (`delivery.require_service()`).

## Установка расширения 1С
Пошагово — в шапке `onec_extension_delivery.bsl`. Кратко:
1. Расширение «nStoreДоставка» → HTTP-сервис `nstore_delivery`, шаблон `/status`, POST → `СтатусPOST`.
2. Снять у расширения «Безопасный режим» и «Защита от опасных действий».
3. Публикация: «Публиковать HTTP-сервисы расширений по умолчанию».
4. Доп. реквизит расходной накладной «Статус доставки» (Строка 50); опционально «Доставка: детали».

Пока сервис не опубликован, `delivery-to-onec` пишет в `delivery.sync_runs` запись `push / skipped`
и не тратит попытки — после установки статусы уйдут автоматически.
Адрес сервиса по умолчанию выводится из `ONEC_ODATA_URL`; переопределить — секрет `ONEC_DELIVERY_HS_URL`
(и `ONEC_HS_USER`/`ONEC_HS_PASSWORD`, если нужен отдельный пользователь).

## Проверка
```sql
select kind, status, stats, error, finished_at from delivery.sync_runs order by id desc limit 10;
select s.*, i.number from delivery.status s join delivery.invoices i using (ref) where onec_pending;
```
