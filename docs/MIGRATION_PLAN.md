# Переезд nstore.kz на новый сайт — план и рекомендации

> Цель: перевести домен **nstore.kz** со старого сайта (InSales) на новый (этот
> репозиторий, Vite+React на Vercel) **безболезненно для SEO** — не потеряв
> позиции и трафик, которые уже есть в Google/Yandex.
>
> Дедлайн: **28.07** (в плане ниже даты рассчитаны на 2026 год — 17 дней с 11.07.
> Если имелся в виду 2027-й, просто растяните буферные периоды, суть та же).

---

## 0. Золотое правило миграции

**НЕ удаляйте старый сайт и не отключайте InSales, пока новый не проиндексирован
и редиректы не проверены.** Домен один и тот же, поэтому «переезд» = смена того,
куда указывает DNS/хостинг nstore.kz. Старый сайт держим включённым на резервном
адресе (напр. `old.nstore.kz`) минимум 2–4 недели как источник данных и страховку
для отката.

Три вещи, потеря которых обнуляет SEO, — их и защищаем:
1. **URL-адреса** старых страниц (уже в индексе) → нужны 301-редиректы.
2. **Контент** страниц (тексты, фото, отзывы) → переносим.
3. **Сигналы доверия** (карточки 2ГИС/Google, ссылки на сайт) → сохраняем домен.

## 2. План по фазам

### Фаза A — Сбор данных (11–14.07). Нужно от вас
- [ ] **Полный список старых URL** — `nstore.kz/sitemap.xml` (или выгрузка из InSales).
- [ ] **YML-фид старого сайта** (Админка InSales → Продвижение → Экспорт →
      Яндекс.Маркет) — ссылка на `.yml`. Нужен для переноса фото и цен.
- [ ] **Подтвердить контакты** для structured data: на сайте указаны
      **+7 700 720 0006 / sales.nstore@gmail.com** — поправить в `src/lib/seo.ts`
      (сейчас там заглушки), добавить точный адрес и координаты склада.
- [ ] Доступы: Google Search Console и Yandex Вебмастер (или заведём заново).

### Фаза B — Перенос контента и фото (14–20.07)
- [ ] **Фото товаров** (на машине с интернетом). Два способа:
  - **Есть YML:** `node scripts/import-images-from-yml.mjs <YML> --cloudinary`
    (точный матч по артикулу).
  - **Нет YML:** `node scripts/scrape-images-from-sitemap.mjs --cloudinary`
    — проходит по товарным URL из `migration/old-sitemap.xml`, тянет фото
    (JSON-LD/og:image) и артикул со страниц, матчит по артикулу или названию.
    Сначала прогон `--dry-run --limit 20` для проверки.
  - Без `--cloudinary` кладёт прямые ссылки на CDN InSales (быстрее, но зависит
    от старого хостинга); с `--cloudinary` — перезаливает в ваш Cloudinary.
- [ ] **Тексты категорий и товаров:** перенести описания (у InSales они есть в том
      же YML / в выгрузке товаров).
- [ ] **Блог** (`/blogs/blog/*`): решить — переносим статьи на новый сайт (полезно
      для SEO) или редиректим на профильные категории.

### Фаза C — Карта 301-редиректов (18–22.07)
- [ ] Из старого sitemap + YML построить карту **старый URL → новый URL**:
  - `/collection/<slug>` → `/catalog/<новый-slug>` (категории, вручную ~10–20 шт);
  - `/product/<slug>` → `/product/<новый-slug>` (товары, автоматически по артикулу/названию);
  - `/blogs/blog/<slug>` → статья на новом сайте или ближайшая категория;
  - всё, чему нет пары, → главная (последний резерв, помечать в отчёте).
- [x] Старый `sitemap.xml` получен → `migration/old-sitemap.xml` (845 URL:
      724 товара, 72 категории, 37 статей блога, 11 страниц).
- [x] Черновик карты категорий/страниц → `migration/redirect-map.json`
      (+ читаемый `migration/redirect-map.md`): 54 категории предложены авто,
      **18 требуют ручного решения**, страницы и блог заданы.
- [ ] Проверить/дозаполнить `migration/redirect-map.json` (18 категорий,
      сверить предложенные с реальными разделами нового `/catalog`).
- [ ] Сгенерировать полную карту (нужен YML для товаров):
      `node scripts/build-redirects.mjs --yml "<YML>"`
      → `redirects.generated.json` (101 редирект категорий/страниц/блога +
      724 товара по артикулу) + `unmapped.txt`.
- [ ] Вставить содержимое `redirects.generated.json` в блок `redirects` `vercel.json`
      (`permanent: true` = 301).
- [ ] **Я доведу карту**, как только пришлёте sitemap/YML.

### Фаза D — Тех. подготовка нового сайта (перед переездом)
- [ ] Проверить, что новый сайт собран и работает на превью-домене Vercel.
- [ ] `robots.txt` и `sitemap.xml` актуальны (уже настроены).
- [ ] Аналитика: Google Analytics 4 + Yandex Metrika с электронной коммерцией.
- [ ] Прогнать Lighthouse/PageSpeed, устранить критичное.

### Фаза E — Переезд DNS (окно ~24–26.07, вечер/ночь — минимум трафика)
1. Снизить TTL DNS заранее (за сутки) до 300 сек — чтобы переключение прошло быстро.
2. Старый сайт продублировать на `old.nstore.kz` (страховка/источник данных).
3. Переключить A/CNAME запись nstore.kz на Vercel, добавить домен в проект Vercel,
   выпустить SSL.
4. Сразу проверить: главная, 5–10 старых URL (должны отдавать **301** на новые),
   robots.txt, sitemap.xml, HTTPS.

### Фаза F — После переезда (26.07 – +4 недели)
- [ ] В Search Console и Yandex Вебмастер: **сменить/подтвердить домен, отправить
      новый sitemap.xml**, запросить переобход.
- [ ] Использовать инструмент «Переезд сайта» в Yandex Вебмастере (если меняется
      структура — указать через 301, Яндекс это учитывает).
- [ ] **Ежедневно смотреть отчёт 404** (Search Console → Покрытие) первые 2 недели,
      дописывать редиректы для всплывших старых URL.
- [ ] Следить за индексацией и позициями. Небольшая просадка на 1–3 недели —
      норма при переезде, восстанавливается при корректных 301.
- [ ] Только после стабилизации (позиции вернулись, 404 закрыты) — выключать
      старый InSales.

## 3. План отката (если что-то пошло не так)
Вернуть DNS-запись nstore.kz обратно на старый хостинг InSales. Поскольку старый
сайт остаётся живым на `old.nstore.kz`, откат — это одна правка DNS (минуты при
низком TTL). Поэтому Фаза E делается в окно низкого трафика.

## 4. Как сделать новый сайт ЛУЧШЕ старого

### 4.1 Контент карточек (сильнее всего влияет на конверсию и SEO)
- **Фото** — заполнить (скрипт готов). Товар без фото почти не покупают.
- **Несколько фото** на товар + зум (в YML их обычно 2–4 — скрипт берёт первое,
  можно расширить на галерею).
- **Характеристики** таблицей (объём, вес, состав, срок годности, страна, штрихкод) —
  и в текст, и в JSON-LD `additionalProperty`.
- **Наличие и мин. партия** явно (для опта критично).

### 4.2 Навигация и поиск
- **Фильтры** в каталоге: по категории, цене, наличию, бренду.
- **Живой поиск** по названию/артикулу (у вас уже есть SearchBox — усилить).
- **Хлебные крошки** на всех страницах (на товарах/категориях уже есть).

### 4.3 Доверие (важно для B2B и для генеративных движков)
- Блок **о доставке и оплате**, зоны и сроки по Астане/РК, отсрочка для B2B.
- **Отзывы** (у вас есть ReviewsBlock) + разметка `AggregateRating`.
- Реквизиты, ИИН/БИН, «плательщик НДС», сертификаты — это уже есть на старом сайте,
  перенести. Повышает доверие и помогает попадать в ответы ИИ.
- **FAQ-блок** с разметкой `FAQPage` («минимальный заказ», «доставка», «условия
  для HoReCa») — генеративные движки любят вопрос-ответ.

### 4.4 Локальное SEO / гео
- Карточки в **2ГИС** и **Google Business Profile** (для Казахстана 2ГИС важнее).
- `LocalBusiness` с точными координатами склада (уже в коде — заполнить реальные).

### 4.5 Производительность
- Бандл крупный: чанк `Tracker` ~840 КБ, `index` ~546 КБ. Разбить через
  `manualChunks` / ленивую загрузку тяжёлых страниц (частично уже lazy).
- Изображения через Cloudinary с авто-форматом (`f_auto,q_auto`) и нужным размером.

### 4.6 Аналитика и контент
- **GA4 + Yandex Metrika** с e-commerce событиями (просмотр товара, добавление в
  корзину, заказ) — без этого не видно, что работает.
- **Блог** под информационные запросы («как выбрать…», «оптом в Астане») — источник
  бесплатного трафика, которого у чистого каталога нет.
